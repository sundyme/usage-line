# usage-line 2D 影片 v2 · 创作简报

## 目标

保留 v1 的气质：暖石墨色的底，插件自己的圆环颜色，中文粗体标题配英文衬线斜体副标题，角落的章节标记，以及 44 秒的节拍和配乐。

在此基础上，把平面排版升级为有景深的 3D 空间：
- 真实透视的动态运镜。
- 我们的 UI 元素丝滑地落进 Claude Code 窗口。
- 每个模块都由镜头运动来介绍。
- 转场自然，并且有创意。
- 内容与插件 1.1.0 一致。

## 视觉原则

1. **真实透视，不是假 3D。** 每个界面元素都是 3D 空间里的一块平面，由透视相机拍摄，近大远小、近快远慢，视差自然产生。背景的点阵铺在远处的一层，镜头一动就有纵深感。
2. **运镜要有动机。** 每一次镜头移动，都是为了把视线带到要讲的那个东西上：
   - 推近，用来看清细节。
   - 横移，从一个模块走到下一个。
   - 环绕，展示空间关系。
   - 回正，回到正面停下来读字。

   不做无意义的晃动；只有一点手持般的微漂，让画面有呼吸感。
3. **运动有重量。** 落下的元素先快后慢，最后带一点极轻的回弹，阴影随高度收紧、变实。缓动统一使用 quint、expo 和弹簧曲线，不用线性。
4. **字要好读。** 标题和副标题锁定在屏幕上，不随透视变形，这样永远清晰；它们也随运动模糊和转场一起变化。数字和界面文字可以在 3D 里，但镜头停下来时必须够大、够正，能读清楚。
5. **界面忠于真实产品。** Claude Code 桌面窗口和终端都是平面、暖灰色。终端的用量行位于 `❯` 输入框上方独占一行，下面是 `? for shortcuts` 提示行，饼形字符用圆环颜色。
6. **转场来自内容本身。** 尽量用匹配剪辑（圆环接圆环、窗口翻面、同一终端换内容）和连续镜头完成转场，而不是硬切或黑场。

## 分镜（时间与配乐节点保持不变）

| 时间 | 镜头 | 运镜 | 转场 |
| --- | --- | --- | --- |
| 0–5.6 | 四个问题分布在不同深度的平面上 | 镜头缓慢向前推进，带一点偏转；问题依次浮现，形成视差 | 四个问题向中心压扁，汇成一条光线 |
| 4.9–10.4 | 光线展开，「一行，全看清。」从线后升起；线收短，变成 usage-line 标志 | 从轻微的侧角缓缓转到正面，再慢慢推近 | 窗口从下方推上来，标志被推出画面 |
| 10–16 | **核心镜头：落入。** Claude Code 桌面窗口以 3/4 透视角斜放在空间里。缓存、5h、7d、上下文四个圆环元素依次从镜头前方落下，翻正、减速，最后带轻微回弹贴进输入框上方的用量行，阴影逐渐收紧 | 镜头环绕到正面；打字、发送，缓存圆环出现涟漪；镜头推近到用量行，四个标注升起 | 镜头冲进缓存圆环，穿越变焦，进入下一镜 |
| 16–24 | 缓存表盘分三层：刻度在后、圆环居中、读数在前 | 镜头缓慢环绕，三层相对滑动；时间推移、最后一分钟琥珀色、过期变红、续上后重回 60:00 | 甩镜横移 |
| 24–32.8 | 5h、7d 两个圆环和 70%/90% 阈值刻度尺放在一张略微倾斜的平面上，上下文圆环在同一空间的更右侧 | 镜头从 5h 推到 7d，掠过阈值尺，再连续横移到上下文圆环；中间不切镜头 | 模糊变焦 |
| 32.5–38 | 桌面窗口在透视中变窄，标签依次收起；随后窗口绕 Y 轴翻面，背面是终端 | 终端按列数变窄：完整标签 → 短标签 → 只剩数字，数字一直都在 | 同一个终端直接进入下一段 |
| 38–41.3 | 同一个终端清空，打出两行安装命令，出现绿色对勾 | 镜头缓慢推近 | 光圈从对勾处展开 |
| 41.3–44 | usage-line 标志与网址 | 从倾斜的近景回正、拉远 | 淡出 |

## 技术路线

用 trailer 的 three.js 引擎渲染：GPU、HDR、bloom、8 个子帧的运动模糊，以及合成转场着色器。v1 的绘制函数和配色直接沿用（`ui.js` 已有同款图元），配乐沿用 `film/out/score.wav`。渲染时降低资源占用：2 个并行页面，进程优先级调低（nice）。
